# Contributing to the Nuclear Science & Engineering Community

First off, thank you for considering a contribution! 💚 This community is built entirely by volunteers, and every correction, resource, and paragraph of content makes a difference.

## Ways to contribute

You don't need to be a nuclear engineer to help. Some ideas, roughly ordered by effort:

- **Fix typos and broken links** — open a pull request (PR) with the fix
- **Suggest a resource** for the [resources](https://github.com/nuclear-community/resources) library
- **Improve an explanation** in [nuclear-101](https://github.com/nuclear-community/nuclear-101) — clearer wording, better examples, a diagram
- **Answer questions** in [Discussions](https://github.com/nuclear-community/.github/discussions)
- **Write or review a learning module** — check a module's issues for "help wanted" items
- **Propose or join a project** in the [incubator](https://github.com/nuclear-community/projects)

## How to submit changes

1. **Discuss first for big changes.** If you want to add a module, restructure content, or start a project, open an issue or Discussion before writing — we'll help you scope it.
2. **Fork & branch.** Fork the repository (or create a branch if you're a member), and name your branch something descriptive: `fix/decay-law-typo`, `add/openmc-resources`.
3. **Make your changes.** Keep PRs focused — one topic per PR makes review faster.
4. **Open a pull request** and fill in the template. A maintainer will review it, usually within a few days.

## Content guidelines

- **Language.** Write in **English**. Keep sentences short and plain — many readers are non-native speakers. When introducing a technical term, define it on first use.
- **Audience.** Assume a motivated beginner unless the module says otherwise. State prerequisites at the top.
- **Free first.** Prefer freely available resources. If a source is paywalled, say so explicitly.
- **Cite your sources.** Every factual claim in learning content should be traceable. Link to the source or list it in the module's resources section.
- **Units & notation.** Use SI units. Be explicit about absorbed dose vs. dose equivalent (Gy vs. Sv), activity units (Bq, with Ci in parentheses on first use), and similar commonly confused quantities.
- **Safety first.** Content must never provide instructions for handling radioactive materials or constructing unsafe experiments. We teach theory and point to licensed, professional practice.
- **Markdown style.** One sentence per line is *not* required; wrap normally. Use tables for structured lists, and keep headings hierarchical (`##` then `###`).
