# Security Policy

## Supported versions

Our repositories are living documents and software projects; fixes apply to the default branch (`main`) only.

## Reporting a vulnerability

Most of our repositories contain educational content, but some community projects include software. If you discover a security vulnerability in any of our code:

1. **Do not open a public issue** describing the vulnerability.
2. Report it privately using [GitHub's private vulnerability reporting](https://docs.github.com/en/code-security/security-advisories/guidance-on-reporting-and-writing-reviews-for-security-vulnerabilities) on the affected repository, or
3. Contact an organization owner directly via GitHub.

Please include a description of the issue, the steps to reproduce it, and its potential impact. We aim to respond within 7 days.

## Scope notes

- Vulnerabilities in **dependencies** of our projects are in scope.
- Broken links, typos, and factual errors in educational content are **not** security issues — please open a regular issue or PR for those.
